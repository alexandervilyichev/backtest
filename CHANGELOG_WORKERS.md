# Changelog: Оптимизация памяти через пул воркеров

## Дата: 23 ноября 2025

## Проблема
При запуске множества стратегий на больших файлах со свечами программа завершалась с ошибкой нехватки памяти (OOM).

## Решение
Реализован пул воркеров (worker pool) для ограничения количества одновременно работающих горутин.

## Изменения

### 1. `internal/app/backtester/types.go`
- Добавлено поле `Workers int` в структуру `Config`
- Позволяет настраивать количество параллельных воркеров

### 2. `cmd/backtester/main.go`
- Добавлен флаг `--workers` для командной строки
- Значение по умолчанию: 0 (автоматически = NumCPU)

### 3. `internal/app/backtester/runner.go`
- Переработан метод `RunAllStrategies` в `ParallelStrategyRunner`
- Вместо запуска всех стратегий одновременно используется пул воркеров
- Количество воркеров ограничено значением из конфига или NumCPU

### 4. Документация
- Создан `MEMORY_OPTIMIZATION.md` с подробным описанием проблемы и решения
- Обновлен `README.md` с информацией о новом флаге `--workers`

## Использование

```bash
# Автоматический режим (использует все CPU ядра)
go run ./cmd/backtester/ -file large_file.json -strategy all

# Ограничение до 4 воркеров
go run ./cmd/backtester/ -file large_file.json -strategy all -workers=4

# Последовательное выполнение (1 воркер)
go run ./cmd/backtester/ -file large_file.json -strategy all -workers=1
```

## Результаты

- **До**: 50 стратегий × 100k свечей → OOM
- **После**: Стабильная работа с контролируемым потреблением памяти
- **Производительность**: Незначительное снижение скорости при малом количестве воркеров, но стабильная работа

## Рекомендации

- Для файлов >50k свечей: используйте `--workers=4` или меньше
- Для файлов 10k-50k свечей: используйте `--workers=6-8`
- Для файлов <10k свечей: используйте автоматический режим (все CPU)
